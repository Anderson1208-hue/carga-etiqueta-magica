# Architecture rules
- CT-e imports prefilter existing CT-e/NF links in bounded queries and insert only missing links; split only the specific duplicate-link conflict on concurrent inserts, never overwrite existing freight or hide other failures.
- The managerial agent uses only authenticated allowlisted read-only report RPCs, never operator-wide data tools or arbitrary SQL; per-user database threads have route-derived IDs and server-only message writes, with deterministic bounded reports and explicit partial-result warnings to preserve security and operational totals.
- Sirius tracking loads the plan and queue in deterministic bounded pages and applies targeted NF filters server-side before pagination, because the Data API cap otherwise silently excludes newer invoices.
- Operator NF consultation displays the confirmed MO corrective photo separately from the original delivery POD, keyed by NF access key; never overwrite operational photo paths when displaying corrections.
- OK Entrega scheduled validation uses a dedicated authenticated consultation endpoint, never the enqueue/transmission job; gate dispatch with the existing RJ business-day calendar to avoid holiday calls, select routing dates through the current Brasília day and page deterministically, preserving original occurrence IDs.
- OK Entrega rejected-photo corrections stage a unique storage object without changing the operational POD, require server-validated approved-operator access and a conditional rejected-row reservation, and transmit only on explicit confirmation; preserve historical images and portal responses and never automatically retry a corrected submission.

- OK Entrega portal consultation is isolated from image transmission; authenticate approved operators and return only allowlisted business data, never portal HTML or authentication responses, to prevent credential leakage and accidental retransmission.
- OK Entrega portal parsing uses a tested shared parser for document-link IDs and validation-result arrays; mirror the portal's actual fields rather than assuming HTML quoting or scalar statuses.
- OK Entrega validation updates verify the original transmitted occurrence belongs to the document and authorized routing date, then read the latest uniquely dated delivery occurrence including manual portal corrections; retain the original transmission ID and never infer approval from unknown or ambiguous results.

- OK Entrega scheduled validation selects only production queue rows still awaiting a final result and sent since the consultation start date (cursor by id, small chained blocks), then resolves their routing date; never scan all routed NFs, because that chain broke silently as volume grew. Manual date consultation still uses the vehicle routing date.

- Keep operator navigation grouped in lateral flyouts within the existing desktop Sidebar, retaining existing route targets and access-hook filters; this reduces menu clutter without changing business workflows or the driver application.
- In RLS policies always wrap no-argument helper checks as `(SELECT public.is_admin())` / `(SELECT public.is_active_operator())`; bare calls run once per row and saturated the database (outages Oct/2026).
- Geocode-cache reads require active profiles in RLS; geocoding endpoints using service credentials must validate the caller and protected profile approval through the shared operator guard, because service credentials bypass RLS.- OK Entrega transmission has its own 15-minute queue-drain schedule calling the send job; never repurpose it for validation consultation, because stuck items are only released when the send job runs.
- Cacau Show (IBAC/IBAE) portal consultation remains read-only; explicitly confirmed rejected-photo replacement uses ibac-corrigir-foto outside the automatic queue, with per-note reservation, current portal validation, verified private remote-image backup and durable phase history; recovery never repeats deletion and never infers approval from upload success.
- Cacau Show per-key portal consultation has no fixed note cap: it pages sent notes since tracking start, walks them by stable key cursor in chained time-budgeted blocks, and backs off on portal rate limits, because a fixed cap silently left notes pending on high-volume days.
- MO image lookup joins the uniquely keyed list row to detail by image OID and documentoIndustria.chaveDoc; retain list validation because the image detail omits it, and reject changed identifiers before replacement.
- MO corrective upload sends the verified complete image-detail DTO with only base64/name replaced, matching its portal UI; pace portal calls and confirm exact stored image before completion, because a minimal DTO can return success without persisting the photo.
- Fiscal monitor (fiscal-monitor function) compares official source pages by text hash once per RJ business day and calls AI only on changed text; alerts never change fiscal rules automatically and require admin approval, keeping recurring cost minimal and rules auditable.
- Route cancellation uses the cancelar_roteirizacao RPC: marks the vehicle cancelled (never deletes it), logs reason/NFs, returns NFs to Preparação, blocks vehicles in transit or with deliveries, and never touches conference, labels, CT-e/MDF-e or SM, so history and issued documents stay intact.
- Overhaul SM generation (overhaul-gerar-sm) logs into the portal with the stored login, creates a portal route origin -> stops in routing order -> last delivery (never "sem rota"), copies only vehicle/tracker data from the vehicle's latest readable SM (skips SMs whose copy form fails, e.g. manual ones), resolves the trip's driver in the portal (CPF, else unique active name match, else bounded name-prefix searches and closest token-aware name with deterministic ties for operator review), fills the portal-required celular from our driver register or falls back to the model SM's contact, registers missing customers from our register with the operational coordinate or the geocoded register address, and marks "gerada" only after the new SM appears in the portal list; an existing SM for the plate on that day always blocks generation unless it is cancelled, excluded or finalized in the portal (no override); failures remain recorded and returned to the operator without calling email delivery, keeping the error observable without notification side effects.
- Chocolate (termo sensível) is classified per NF in the database (notas_fiscais.termo_sensivel via triggers: whole-shipper CNPJ roots, else any item matching a product flagged termo_sensivel or segment 10-Chocolates); a carga only gets upgraded to CHOCOLATE, never downgraded, so the operator no longer chooses the type and legacy loads stay intact.
- OK Entrega enqueue fires both when a vehicle's prestação de contas closes and when a baixa with photo is inserted/updated after closure (trigger on baixas_entrega calling okentrega-enfileirar per vehicle), because late baixas otherwise never entered the queue.
- Scheduled OK Entrega/IBAC consultations run through integracao-guardiao: a failed run arms a temporary 10-minute retry job (max 5 attempts, unscheduled on success or exhaustion) and emails arquivostlm on the 5th failure, so silent missed rounds surface without a permanent poller.
